## Recommended Representation

### Historical Proposal Before Bake

Main reports that baseline replay restores the desired gradual behavior in all three forest cases. Therefore the immediate candidate does **not** require a new spatial front-surface texture: gate the already-reviewed legacy spatial-depth behavior with an independently authored canopy mask. Nash/main approved per-pixel B0=existing support-profile mode, B1=canopy mode, including pixels whose R/ID remains0. Preserve R IDs everywhere; G is authored canopy coverage only inside the gate; outside it retain every v1 byte. Keep ground-v2 unchanged. Intended future output names: `shire-object-instances-v2.png` and provenance `shire-object-occlusion-v3.json`. No candidate asset baked by this investigation.

Existing field segmentation is not a trustworthy canopy gate. `scripts/atlas-field/build-field.py` derives R from raised-object heuristics, water/building masks, route carving and morphology; it does not distinguish tall foliage from low house flowerbeds or solid structures. Current instance coverage is also insufficient for case1. Recommend one image-generated **binary annotation proposal from the original map**, then visual/numeric registration checks, not blind acceptance.

Prompt recommendation supplied to main: exact1536x1024; white only elevated tree crowns and hanging leafy branches, including missing foliage between simplified instance silhouettes; follow true contours and retain branch/background gaps. Black ground, paths, water, rocks, fences, structures/roofs, tractor/crane/trailer, exposed roots/trunk bases and all low shrubs/flowerbeds, especially house-side flowering bushes. No geometry shift, enlargement, simplification, gradients or new scenery. Inspect house and vehicle exclusions plus forest coverage before thresholding/baking; reject overlap with verified house/vehicle IDs. No runtime ID0-wide fallback and no saved-case coordinate patches. Main owns image generation. The broader surface/volume recommendations below remain optional future work, not prerequisites for this bounded baseline-behavior restoration.

- Preserve opaque profile ordering for verified hard objects, especially house1 and tractor2/v2 wheel-support row. Do not reintroduce the old depth feather/translucency globally or modify navigation to disguise occlusion.
- Introduce an authored per-instance/material mode table: hard support-profile versus vegetation spatial-depth. A B-channel mode flag is a possible new texture contract, but existing runtime validation requires B0, so it must be explicitly versioned/coordinated, not written into current assets. No flag/texture change performed here.
- `root-bottom` is only a contact derivation method, **not** a vegetation class. Current generic components include rocks, fences and other unreviewed shapes; reserved-color suffix labels also lack semantic certainty. IDs55/160/174 are visually confirmed plant candidates;83/120 also depict trees in the inspected crops. Use an explicit reviewed instance list, or author segmentation classes broadly, without saved-case coordinates in code. Do not silently mark every root-bottom object as foliage.
- Vegetation needs a per-scene-pixel front-surface/occlusion-depth field plus coverage, or layered front/back surfaces for genuine volume. Align scene and character comparison in one calibrated depth convention (alternatively bake equivalent per-pixel foot-depth/Y thresholds). Spatially varying surface thresholds allow leaves/branches to cover different body regions progressively, instead of toggling a whole silhouette at its root. Original artistic depth can guide relative shape/edges but does not uniquely recover canopy volume or terrain; any conversion remains an authored approximation requiring review.
- Keep opaque interior ordering and reserve fractional coverage for foliage edges/holes. Merely feathering the same constant per-instance root threshold fades a large part of the character uniformly and does not restore progressive canopy coverage. Separate trunk/foliage materials or a second surface layer may be needed where one depth per pixel cannot represent interpenetration.
- Refine missing vegetation coverage in case1 using registered original/depth evidence. Preserve ground openings and hard-object masks. A vegetation mode alone cannot occlude ID0 pixels.

Acceptance should sweep through threshold neighborhoods with a fixed sprite frame as well as the actual animation, and include nearby plants not used in these marks. Recheck house entrance/bush, tractor foreground and trailer rear after any vegetation mode addition. No new bake is warranted until the comparison domain and reviewed vegetation labels are agreed.
